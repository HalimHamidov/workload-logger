## Что делает эта программа — простым языком

### Одной строкой:
> Программа наблюдает за тем, **как** вы печатаете и двигаете мышью (но не **что** вы пишете),
> и по этим паттернам определяет, насколько вы устали или перегружены умственно.

## Блок 1 — Сборщик данных (Логгер)

### Что он делает
Работает в фоновом режиме и незаметно отслеживает:

**Клавиатура:**
- Когда нажата и отпущена клавиша (время в миллисекундах)
- Тип клавиши: буква/цифра → записывается как `CHAR` (не сама буква!)
- Backspace, Delete, Ctrl+Backspace → фиксируется как «удаление»
- Enter, Tab, стрелки, Ctrl, Shift → записываются как категория

**Мышь:**
- Координаты курсора каждые ~16 мс (60 раз в секунду)
- Клики: какая кнопка, когда нажата, когда отпущена
- Прокрутка: направление и сила

### Что он НЕ делает (конфиденциальность)
- ❌ Не записывает, какие буквы вы нажимаете
- ❌ Не хранит слова или предложения
- ❌ Не делает скриншоты
- ❌ Не отправляет данные в интернет
- ✅ Все данные остаются только на вашем компьютере

### Пример выходного файла `input_events.jsonl`
```json
{"type": "key_down", "key_category": "CHAR", "timestamp": 1741500000.123}
{"type": "key_down", "key_category": "BACKSPACE", "timestamp": 1741500000.456}
{"type": "mouse_move", "x": 854, "y": 432, "timestamp": 1741500000.789}
{"type": "mouse_click", "button": "left", "pressed": true, "x": 854, "y": 432, "timestamp": 1741500001.0}
```

## Блок 2 — Обработчик признаков (Feature Engineering)

### Что он делает
Каждые **5 секунд** берёт накопленные события и вычисляет из них **числовые признаки**:

### Группа А — Признаки мыши (базовые)
| Признак | Что измеряет | Зачем |
|---|---|---|
| `mouse_distance` | Сколько пикселей прошёл курсор | При усталости движения хаотичнее или наоборот скованнее |
| `mouse_speed_mean` | Средняя скорость курсора | Высокая скорость = спешка = стресс |
| `mouse_speed_std` | Разброс скорости | Нервозность проявляется в неровных движениях |
| `mouse_idle_ratio` | Доля времени без движения | Высокий idle = задумались или устали |
| `click_rate` | Количество кликов в секунду | Частые клики = суетливость |
| `click_hold_mean` | Среднее время удержания клика | При усталости удержание длиннее |

### Группа Б — Признаки траекторий мыши
Программа разбивает движение курсора на отдельные **траектории** (непрерывные движения без пауз).
Каждая траектория анализируется отдельно:

| Признак | Что измеряет | Зачем |
|---|---|---|
| `traj_efficiency` | Насколько прямолинейно идёт курсор (0–1) | При когнитивной нагрузке кривые более извилистые |
| `traj_curvature` | Степень изгиба траектории | Трясущиеся/неточные движения = высокая нагрузка |
| `traj_direction_consistency` | Постоянство направления движения | Резкие смены = нерешительность |
| `traj_SAT` | Скорость × (1 − точность) | Компромисс между скоростью и точностью |

### Группа В — Признаки клавиатуры
| Признак | Что измеряет | Зачем |
|---|---|---|
| `typing_rate` | Символов в секунду | При высокой нагрузке скорость падает |
| `hold_time_mean` | Среднее время нажатия клавиши | При усталости дольше держат клавишу |
| `pause_mean` | Пауза между нажатиями клавиш | Длинные паузы = думаете дольше = сложнее задача |
| `pause_std` | Разброс пауз | Нерегулярный ритм = когнитивная перегрузка |

### Группа Г — Оценка удалений
| Признак | Что измеряет | Зачем |
|---|---|---|
| `del_total` | Сколько символов удалено за окно | Много удалений = ошибки = перегрузка |
| `del_weighted` | Взвешенное удаление (с учётом уверенности оценки) | Точнее учитывает Ctrl+Backspace и выделение |
| `del_conf_score` | Насколько уверена оценка удалений (0–1) | Качество данных о удалениях |
| `del_rate` | Удалений в секунду | Интенсивность редактирования |

### Итог обработки
За час работы при 5-секундных окнах → **720 строк** с признаками.
Затем из них вычисляются **среднее, стандартное отклонение, минимум и максимум**
по каждому признаку → итоговая строка из **134 чисел** на сессию.

## Блок 3 — Анкета NASA-TLX

### Что это
**NASA Task Load Index** — стандартная научная методика измерения умственной нагрузки,
разработанная NASA в 1988 году. Используется в авиации, медицине, образовании.

### Как работает
После каждой рабочей сессии появляется окно с **5 ползунками** (0–100):

```
┌────────────────────────────────────────────────────┐
│  Оцените вашу нагрузку за последнюю сессию         │
│                                                    │
│  Умственная нагрузка    [──────●──────]  55        │
│  Временное давление     [───●──────────]  30        │
│  Собственная эффектив.  [──────────●──]  75        │
│  Усилие                 [────●──────── ]  40        │
│  Уровень фрустрации     [──────●──────]  50        │
│                                                    │
│  Средний TLX: 50.0                                 │
│                                                    │
│              [ Сохранить ]                         │
└────────────────────────────────────────────────────┘
```

### Что означает каждая шкала
| Шкала | 0 означает | 100 означает |
|---|---|---|
| Умственная нагрузка | Очень лёгкая задача | Очень сложная задача |
| Временное давление | Работал в своём темпе | Постоянная спешка |
| Собственная эффективность | Всё делал идеально | Очень много ошибок |
| Усилие | Практически не старался | Работал на пределе |
| Уровень фрустрации | Спокойно и комфортно | Раздражение, стресс |

### Мини-анкета каждые 2 минуты
Дополнительно **каждые 2 минуты** появляется быстрый попап:
```
┌─────────────────────────────┐
│  Быстрая оценка (2 вопроса) │
│                             │
│  Умственная нагрузка [●] 7  │
│  Фрустрация          [●] 4  │
│                             │
│         [ ОК ]              │
└─────────────────────────────┘
```
Это позволяет собрать **30 меток за час** вместо одной — критически важно для обучения модели.

## Блок 4 — Машинное обучение

### Задача модели
Взять 134 числа из сессии (как вы печатали и двигали мышью) и предсказать
ваши оценки по 6 целевым переменным:

```
[134 признака поведения] → модель → предсказание:
                                     - Умственная нагрузка: 62
                                     - Временное давление: 38
                                     - Эффективность: 71
                                     - Усилие: 55
                                     - Фрустрация: 44
                                     - Средний TLX: 54
```

### Какая модель используется
**Ridge Regression** — линейная регрессия с L2-регуляризацией:
- Устойчива при большом числе признаков
- Работает даже при небольшом датасете
- Параметр `alpha` подбирается автоматически: [0.01, 0.1, 1, 10, 100, 1000, 10000]

### Как оценивается качество
Метод **Leave-One-Out Cross-Validation (LOO)**:
- Для каждой сессии: обучаем модель на всех остальных, предсказываем эту
- Получаем честную оценку без переобучения

### Текущие результаты (пилот, 7 сессий)
| Целевая переменная | MAE | RMSE | R² |
|---|---|---|---|
| Умственная нагрузка | 31.1 | 34.6 | −0.61 |
| Временное давление | 26.1 | 30.2 | −0.43 |
| Эффективность | 24.6 | 28.4 | −0.57 |
| Усилие | 25.6 | 28.2 | −0.53 |
| Фрустрация | 31.6 | 40.7 | −0.95 |
| Средний TLX | 18.6 | 21.5 | −0.57 |

**Почему R² отрицательный?** Всего 7 сессий при 134 признаках — модель не может обучиться.
Это нормально для пилота. При 50+ сессиях ожидается положительный R².

## Блок 5 — Интерактивный дашборд

### Вкладка 1: Живой монитор сессии
Показывает прямо во время работы:
- Текущая скорость печати (символов/сек)
- Скорость и хаотичность мыши
- Доля времени простоя
- Оценочный уровень нагрузки (по текущей модели)

### Вкладка 2: История сессий
- Таблица всех сессий с цветовой кодировкой TLX (зелёный=низкий, красный=высокий)
- При выборе сессии:
  - Графики изменения признаков по времени
  - Тепловая карта движений мыши
  - Радарная диаграмма NASA-TLX

### Вкладка 3: Анализ модели
- Топ-20 самых важных признаков (по коэффициентам Ridge)
- PCA-диаграмма сессий (раскрашена по уровню нагрузки)
- График «предсказано vs реально»

### Вкладка 4: Сравнение участников
- Сравнение паттернов между разными участниками
- Определение, доминирует ли стиль конкретного человека над сигналом

## Чего НЕ хватает для идеального результата прямо сейчас

| Проблема | Влияние | Решение |
|---|---|---|
| Мало данных (7 сессий) | Модель не обучается → R² < 0 | Собрать 50–200 сессий |
| Мало участников (2 человека) | Индивидуальный стиль перебивает сигнал | Добавить 5–10 участников |
| Метки после всей сессии | Не точно отражает моменты пиков | Мини-анкеты каждые 2 мин (уже в плане) |
| Смешанные типы задач | Разные паттерны для разных задач | Раздельные модели по типу задачи |
| 134 признака при малом n | Переобучение, нестабильность | PCA или отбор признаков |

**Главный вывод:** Система спроектирована правильно. Единственный барьер — объём данных.
Программа сама решает эту проблему, собирая данные каждый раз при использовании.

## Работа при закрытии крышки ноутбука

### Проблема
Пользователь закрывает крышку → ноутбук уходит в спящий режим (Suspend/Sleep).
Все процессы приостанавливаются. При открытии крышки Windows «просыпается»,
но `pynput`-слушатели (keyboard/mouse listeners) **не всегда восстанавливаются корректно**:
они могут зависнуть, пропускать события или полностью перестать работать.

### Что произойдёт без специальной обработки

```
Пользователь открывает ноутбук утром:
  → Программа НЕ запущена → данные не собираются ❌

Если программа была запущена и ноутбук ушёл в сон:
  → pynput-слушатели зависают после пробуждения → данные не собираются ❌

Если пользователь вручную перезапускает программу:
  → Работает, но это неудобно → пользователь забудет → данные теряются ❌
```

### Решение: три уровня защиты

#### Уровень 1 — Автозапуск при включении Windows
Программа запускается автоматически при каждом входе в систему.
Реализация через **Планировщик задач Windows** (Task Scheduler):

```
Триггер:  При входе пользователя в систему
Действие: python C:\...\workload_logger\main.py --tray
Параметры: запускать с наивысшими привилегиями — НЕТ (не нужно)
           запускать только при наличии пользователя — ДА
```

Или через папку автозапуска:
```
%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\
→ положить ярлык на main.py
```

#### Уровень 2 — Обнаружение сна и пробуждения
Программа подписывается на системные события питания Windows.
При **засыпании** — корректно завершает текущую сессию и сохраняет данные.
При **пробуждении** — автоматически начинает новую сессию.

```python
# Использует win32api (библиотека pywin32)
import win32api
import win32con
import win32gui

class PowerEventHandler:
    """Слушает события питания Windows (сон/пробуждение)."""

    def handle_sleep(self):
        """Вызывается ДО ухода в спящий режим."""
        logger.stop_session()           # остановить сбор данных
        show_tlx_survey()               # показать анкету (опционально)
        save_session_to_disk()          # сохранить всё на диск

    def handle_wake(self):
        """Вызывается ПОСЛЕ пробуждения."""
        restart_pynput_listeners()      # пересоздать слушателей
        logger.start_new_session()      # начать новую сессию
        tray_icon.notify("Логгер возобновлён")
```

#### Уровень 3 — Иконка в системном трее (фоновый режим)
Программа работает как **фоновый процесс с иконкой в трее** (правый нижний угол экрана),
а не как обычное окно. Пользователь видит иконку и знает, что всё работает.

```
Правый клик на иконке в трее:
  ┌─────────────────────────────┐
  │  ● Логгер активен (12 мин)  │
  │  ─────────────────────────  │
  │  Открыть дашборд            │
  │  Завершить сессию сейчас    │
  │  Пауза                      │
  │  ─────────────────────────  │
  │  Выход                      │
  └─────────────────────────────┘
```

```python
            pystray.MenuItem("Открыть дашборд", open_dashboard),
            pystray.MenuItem("Завершить сессию", end_session),
            pystray.MenuItem("Выход", quit_app),
        )
    )
    icon.run()  # блокирующий вызов — запускать в отдельном потоке
```

### Когда показывать анкету NASA-TLX?

Три варианта (выбирается в `config.yaml`):

| Вариант | Когда показывать | Плюсы | Минусы |
|---|---|---|---|
| `on_sleep` | При каждом закрытии крышки | Сразу после активности | Надоедает при коротких паузах |
| `on_manual_stop` | Только при ручном "Завершить сессию" | Не мешает | Пользователь может забыть |
| `min_session_minutes: 20` | Только если сессия длилась >20 мин | Баланс | Рекомендуется ✅ |

```yaml
# config.yaml
survey:
  show_tlx_on: "min_session_minutes"  # on_sleep | on_manual_stop | min_session_minutes
  min_session_minutes: 20             # показывать анкету только если сессия > 20 минут
  mini_tlx_interval_minutes: 2
```
